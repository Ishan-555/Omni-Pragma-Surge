Where its predecessors shouted commands at the engine, Pragmata-Omni-Override *whispers*. It negotiates. It rewrites. And the result is a smoother, more poetic relationship between you, your avatar, and the laws of simulated physics.

## 🌟 The Vision Behind the Name

The word **"Pragmata"** hails from the Greek *pragma* — a deed, an act, a thing done. It speaks to consequence, to tangibility, to the quiet power of doing. **"Omni"** gestures toward totality, and **"Override"** is the spark — the moment where the ordinary loop is interrupted by something curious and intentional.

Together, these words form a manifesto: *every action you take in a simulated world should feel like it truly mattered, even when you're bending the rules to your will.*

Pragmata-Omni-Override is not a wrecking ball. It's a tuning fork. It resonates with the underlying rhythm of the engine and asks, gently but firmly: *what if we played it another way?*

---

## 🧠 What Does It Actually Do?

At its core, this project provides a **non-invasive augmentation layer** that interacts with client-side runtime behavior inside a specific class of motion-centric simulation titles. It doesn't rewrite binaries, it doesn't patch executables from disk, and it doesn't alter the host system in any destructive way. Instead, it operates as a **runtime companion** — listening, interpreting, and re-framing the values that flow through the engine's memory space.

Think of it as a translator standing between you and a very bureaucratic physics engine. You say "I'd like to fly." The engine says "Here is a list of reasons you cannot." The translator nods sagely, then quietly hands the engine a revised edition of the rulebook.

The outcome? An experience where **verticality is optional**, **momentum is cooperative**, and **depletion is a memory rather than a mechanic.**

## 🕹️ Module Breakdown

The repository is organized into several conceptual modules, each with its own domain of responsibility. Below is a high-level walkthrough — not an instruction manual, but a friendly guided tour.

### Module 1 — `core/override`

The beating heart. This module hosts the foundational logic that binds the suite to the runtime environment. It maintains the **negotiation loop** between user intent and engine state, forever balancing responsiveness against stability.

### Module 2 — `kinetics/propulsion`

Responsible for all things airborne. It manages thrust simulation, drag harmonization, and the delicate ceiling of vertical velocity. Its guiding principle is **grace, not greed** — flight should feel earned in feel, even if it's gifted in mechanics.

### Module 3 — `vitals/resilience`

Manages the integrity of the avatar's state signals. Instead of simply pinning values, it uses a smoothing algorithm so external observers (and the engine itself) never see jarring discontinuities.

### Module 4 — `perception/temporal`

Home to the time compression utilities. This is the module that lets you feel like you're in a film scene rather than a frantic arcade loop.

### Module 5 — `interface/hud`

The visual layer. Minimalist by design, configurable by obsession. Every element can be repositioned, hidden, or re-themed.

### Module 6 — `persistence/profiles`

Handles save-and-restore semantics. Your favorite configuration presets live here, waiting patiently between sessions.

## 📱 Responsive Interface Philosophy

The overlay isn't a monolithic window. It's a **fluid arrangement** that adapts to resolution, aspect ratio, and DPI scaling. Whether you're on a modest laptop display or an ultrawide monitor, the layout honors your screen real estate with respect.

Key principles of the responsive design:

1. **Non-blocking placement** — Panels avoid central sightlines by default.
2. **Adaptive scaling** — Fonts and controls scale gracefully with system DPI.
3. **Gesture and hotkey parity** — Every action is reachable via both input styles.
4. **Colorblind-aware palettes** — Alternate themes include high-contrast variants.

## 🛡️ Safety, Ethics & Community Charter

We hold ourselves to a charter that governs how this project interacts with the world:
